# Agent Memory

这是一个跨 agent 的工程记忆区。它只依赖 Obsidian vault 中的 Markdown 文件和目录约定，Codex、Cursor、Claude Code、Gemini CLI 或其他能读写文件的 agent 都应该按同一套规则使用。

## 核心原则

- 项目上下文跟着项目走：当前任务、项目私有决策、临时代码细节、未完成事项，应该留在对应项目仓库或项目文档中。
- Obsidian 只保存跨项目可复用的知识：架构模式、技术栈经验、业务流程、经验教训、个人偏好、AI 协作规则。
- 正式知识库必须经过审核：agent 不直接写入正式分类，默认先写入 `inbox/`。
- 读取时保持克制：agent 只读取和当前项目相关的少量笔记，并在回答中说明引用了哪些记忆来源。
- 不记录敏感信息：账号、密钥、客户隐私、未公开商业信息、仓库私有细节不得进入这里。

## 标准触发语

### 整理到 Obsidian 工程记忆

当用户说这句话或同义表达时，agent 应该：

1. 回顾当前会话或项目中可复用的内容。
2. 排除只属于当前项目的上下文。
3. 使用 `templates/inbox-capture.md` 的结构创建一条候选摘录。
4. 写入 `inbox/YYYY-MM-DD-topic.md`。
5. 不移动到正式分类，等待用户审核。

### 读取工程记忆

当用户说这句话或同义表达时，agent 应该：

1. 先读取本文件和 `index.md`。
2. 根据当前项目的技术栈、业务域、任务类型选择相关分类。
3. 只读取少量相关笔记，避免把整个 vault 塞进上下文。
4. 在后续计划或实现中说明使用了哪些记忆。

## 分类

- `architecture/`：架构模式、模块边界、数据流、工程组织方式。
- `tech-stacks/`：框架、库、工具链、运行时、测试策略经验。
- `business-flows/`：业务流程、领域模型、角色和状态流转。
- `lessons/`：踩坑、调试经验、判断原则、复盘结论。
- `preferences/`：个人偏好、AI 协作规则、代码风格和工作方式。
- `inbox/`：待审核候选摘录。
- `templates/`：摘录和正式笔记模板。

## Agent 写入规则

- 默认只写 `inbox/`，除非用户明确要求归档到正式分类。
- 每条候选摘录必须包含来源项目、可复用范围、分类建议和置信度。
- 如果内容只对当前项目有用，不写入这里。
- 如果内容可能泄露敏感信息，停止并向用户确认。
- 如果同类笔记已存在，优先建议更新现有笔记，而不是创建重复笔记。
